# API、错误与可观测性

- API 请求和响应使用清晰的 DTO；前端在边界用 Zod 校验不可信数据，后端在入口验证请求并返回稳定的错误码/错误结构。
- 领域错误、权限错误、参数错误和基础设施故障分别处理；不向客户端泄露堆栈或内部实现细节。
- 使用 OpenTelemetry 采集关键请求、用例、数据库访问、外部调用、消息处理和后台作业的 trace 与 metrics；按需将日志关联 `trace_id`/`span_id`，统一使用可配置的 OTLP 导出、资源标识和采样策略。
- HTTP、gRPC、RabbitMQ 等跨进程调用遵循标准 trace context 传递；JobRunr 作业携带必要的关联标识，避免在作业参数中传递完整上下文对象。记录关键用例、作业与消息的结果及耗时。
- 日志和观测属性不得包含密码、令牌或敏感原文；指标标签避免用户 ID、订单 ID 等高基数值。为外部调用设置超时，并按操作的幂等性制定重试策略。
- 多语言：语言由请求决定（`Accept-Language` 或显式语言参数），不依赖服务实例的默认 Locale 和时区。错误响应用稳定错误码和结构化字段，文案由客户端渲染；只有服务端必须产出文案的场景（邮件、推送、模板、PDF）才在服务端本地化，并与前端共用同一套语言标识和 key 约定；至少覆盖 `zh-CN` 和 `en`，其他取值按回退链处理。时间戳以 UTC 存储，展示格式化交给客户端或按请求时区处理。
