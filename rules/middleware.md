# 中间件使用边界

- PostgreSQL（PG）：持久化的主要事实来源。schema 变更通过 Flyway 版本化迁移脚本管理；明确约束、索引和事务范围，关键不变量尽可能由数据库约束与领域校验共同保障。
- Caffeine：用于单进程内可重建数据的本地缓存；必须配置最大容量、过期/刷新策略和失效方式，并明确缓存未命中及加载失败时的行为。不得依赖它实现跨实例共享或强一致性，多实例协调场景使用 Redis 等外部方案。
- Redis：用于缓存、短时状态或确有需要的协调场景；不作为默认事实来源。定义 key 命名、TTL、失效策略和缓存不可用时的行为。
- RabbitMQ：用于异步事件/任务分发。定义消息版本、持久化、确认方式、重试上限和死信处理；消费者必须考虑重复投递并尽可能幂等。
- JobRunr：用于可追踪的后台作业与定时作业。作业参数使用可稳定序列化的标识或数据，不传数据库连接/领域对象快照；执行逻辑可重试、可观察。
- RabbitMQ 与 JobRunr 的用途应区分：跨服务事件和消息消费使用 RabbitMQ，应用内后台执行与调度使用 JobRunr；不要为同一任务同时建立两套无明确理由的调度机制。
